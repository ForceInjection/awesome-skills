# 失败族清单（self-review 第 4 步的执行面）

六族，规则按「族 + 序号」编号（A1…F6）。每族先给**速查表**（一句话），表后**细则**按编号展开完整查法与实例；引用规则直接用编号（如「见 C3」「按 A2 补变异」）。
逐族问一遍；中了的写进结论（已修 / 待定 / 不成立）。

## A. 判据族——最贵的一族：判据错了，全绿也没有意义

| 编号 | 症状                           | 怎么查（速查）               |
| ---- | ------------------------------ | ---------------------------- |
| A1   | 判据与被判对象错位             | 对齐生产调用点的实参形态     |
| A2   | 判据恒真（没判别力）           | 已知正反例 + 新断言最小变异  |
| A3   | 分组/口径与时钟或实现细节耦合  | 分组键与时钟无关，反例轮先验 |
| A4   | 阈值改了但判据集没记版         | 改阈值查记版表落行           |
| A5   | 缺数据 / 不适用 / 判负三者混用 | 三者可分且可观测             |
| A6   | 桩与生产契约不一致             | 逐条对照守卫与失败路径       |
| A7   | 插桩字段恒零                   | 问累加点在哪，配字段齐全回归 |
| A8   | 诊断代码的类型契约错           | 逐值问生产类型               |

**A1 判据与被判对象错位**（形态 / 单位 / 索引域）
判据入参形态 vs **生产调用点实参**逐处对齐（敲 `grep` 看调用点怎么构造）；自问"我的下标是什么域、对方按什么域索引"。
例：守卫函数要**节点对象**，生产传的是 **id 列表** ⇒ `getattr` 恒空 ⇒ 守卫结构性失效，而单测全喂对象 ⇒ 整片绿灯。

**A2 判据恒真**（没判别力）
造**已知反例**跑：检测不出 = 恒绿；再造**已知正例**跑：报错 = 假阳性。两者都过才算成立。**新写 / 加强的断言另做一次最小变异**：把被测的保护摘掉（回滚 / 校验 / 守卫），断言**必须变红**——变异下仍绿 = 无判别力。
例：`grep -c '<pat>' == 0` 判 PASS——模式串写错时恒绿；`-qF` 子串匹配让**相近的无关词**也算通过。变异实证：某"回滚必报错"断言原写法只断言**首个**失败项 ⇒ 无回滚也恒绿；改成"先要≈全容量再要超容量"后，摘掉被测的释放调用，该断言立刻变红。

**A3 分组/口径与墙上时钟或实现细节耦合**
分组键必须与时钟无关（**步序对齐**）；先在已知反例轮上验判别力。
例：按**秒**分组 ⇒ 同一步跨秒落盘被当成分裂（假阳性）；按 `(rids,n)` 分组 ⇒ 真分歧被拆开漏判（假阴性）。

**A4 阈值/口径改了但判据集没记版**
阈值是判据的一部分 ⇒ 改阈值就查记版表有没有落行。
例：落地率门槛 0.20 若不落记版，"本行之前的轮不可与之后对读"就无从谈起。

**A5 缺数据 / 不适用 / 判负三者混用**
三者必须**可分且可观测**（各有独立读数位）；判决只有两态时，理由栏写"缺数据"，别发明第三态。
例：把"没采到证据"写成"通过"；真机臂每轮背一条消不掉的"不适用" ❌。

**A6 桩与生产契约不一致**（桩缺生产的守卫 / 幂等 / one-shot / 失败分支）
逐条对照被替换对象的**守卫与失败路径**：早期 `return`、幂等闩、one-shot、`except` 分支——生产有而桩没有 = 该类 bug 在单测里**不存在**。
例：某注册接口首行 `if self._ready: return`（one-shot），桩没有 ⇒ "补注册被静默吞掉"整类 bug 恒绿、真机才 500。**修法 = 桩复刻守卫**，并写一条"迟到注册必须被判 False"的用例。

**A7 插桩字段恒零**（假读数被当成"无开销"）
每个计时 / 计数字段在产出前问一句"它的**累加点**在哪"；新增插桩配一条"字段齐全"回归（改名 / 丢字段 / NameError 当场红）。**字段被读成结论时错得更远**——宁可删掉恒零字段。
例：三个计时字段初始化后从不累加、恒打 0.0 ⇒ 误判"非 DMA 开销可忽略"；真值藏在计时窗外（ref/unref 合计 17-46 ms，补测才露头）。

**A8 诊断代码的类型契约错**（探针读值的类型 ≠ 生产实际类型）——同 A1 族，但后果是**探针自己把宿主进程打崩**
每个新探针逐值问"**生产里它是什么类型**"：`torch.Tensor` **不能**走 `x or []` / `if x`（`bool(tensor)` 对多元素张量直接 `RuntimeError`），要 `.numel()`；序列走 `len()`。探针体**整段裹 try/except 且降级要留痕**（探针只许降级、不许带崩）。回归**按生产形态喂参**（tensor 就喂 tensor）+ 变异自证（把探针退回旧写法 ⇒ 必须红）。
例：边界探针写 `len(getattr(item,"device_value",[]) or [])`，而该值是 tensor ⇒ 启动 30 s、warmup 首次步边界兑现即 `RuntimeError: Boolean value of Tensor…` ⇒ 四 rank 同刻 SIGQUIT，容器被启动脚本按超时收掉（长轮**一次没跑成**）。

## B. 失败方向族——会删 / 会覆盖的动作必须保守

| 编号 | 症状                        | 怎么查（速查）       |
| ---- | --------------------------- | -------------------- |
| B1   | 破坏性动作的守卫不全        | 列失败路径逐条问     |
| B2   | fail-open：拿不到判决就放行 | 问"判不了会怎样"     |
| B3   | 静默降级                    | 查柔取分支有没有留痕 |

**B1 破坏性动作的守卫不全**
逐条列失败路径（输入为空 / 目标不存在 / 命令失败 / 管道吞码），问"每条各会发生什么"。
例：删远端文件前三条：目标在位、待删清单非空、**待删数 ≠ 全集**（后者=基准失真，拒绝删）。

**B2 fail-open**：拿不到判决就放行
问"这条判不了的路径走下去会怎样"；跨副本一致性的判据失败必须 fail-closed。
例：表决拿不到判决 ⇒ 放行 ⇒ 各 rank 各判各的 ⇒ 批形状分叉 ⇒ 挂死。

**B3 静默降级**：出错后柔取默认值继续跑
逐个看 `except: pass` / `return None` / `|| true` **有没有留痕**——柔取与"本来没事"同形就等于没有判据。
例：分配失败 `rollback + return None` 一行日志不打，因果只能靠"该出现的行没出现"反推。

## C. 静默失败族——"命令看起来成功了，实际没落"

| 编号 | 症状                       | 怎么查（速查）                       |
| ---- | -------------------------- | ------------------------------------ |
| C1   | 写死的默认值               | 坐标类只读单一源、缺失报错           |
| C2   | 截断 / 限频吞证据          | 问被吞掉的是不是正好要看的           |
| C3   | 命令替换/管道/赋值吞退出码 | 查 set -e / pipefail；取证命令同样算 |
| C4   | 参数没进容器 / 设了没生效  | 设了就断言；默认值别显式传           |

**C1 写死的默认值**把"跑错"降级成"静默"
坐标类（路径/主机/镜像 tag/树名）是否只读**单一源**、缺失时**报错**而不是退回字面量。
例：两个脚本各写死一份默认树 ⇒ 各自落到**不同的树**，同步了另一条线的代码而 health 照样 200。

**C2 截断 / 限频吞证据**
见 `| head -N`、`首 N + 每 M` 就问：被吞掉的那部分会不会正好是要看的。
例：集合差异 `| head -10` ⇒ 21 个残留每轮只露 10 个，逐轮 rm 三轮才清完。

**C3 命令替换 / 管道 / 赋值吞退出码**
`$(...)` 的返回值有没有被检查；脚本有没有 `set -e`；**管道**有没有 `set -o pipefail`。**评审者自己的取证命令同样算**——`ssh … | tail` 的退出码是 `tail` 的。
例：远端 `cd` 失败 ⇒ 输出为空 ⇒ 本地判成"无残留"；`ssh host '… | tail -8'` 远端失败静默通过（本轮实证：e2e 的通过与否是靠人工读 `PASS` 定的，退出码没作数）。

**C4 参数没进容器 / 设了没生效**
设了就要**断言**（`docker exec env | grep -qx`）；默认值**别显式传**（传了就再证明不了"不传也对"）。
例：漏传 `-e` 项 ⇒ 树自检整场不跑、心跳全 0，日志上看不出来。

## D. 口径一致族——文档 vs 实现

| 编号 | 症状                       | 怎么查（速查）                  |
| ---- | -------------------------- | ------------------------------- |
| D1   | 计数 / 条数 / 阈值两边不等 | 写了数字的当场数一遍            |
| D2   | 改名后引用面没跟           | 全仓 grep 旧名                  |
| D3   | 悬空引用                   | 移动删除后搜引用、改落点指针    |
| D4   | 结论与实现方向相反         | 理由栏写"缺数据"，别造第三态    |
| D5   | 动机句腐坏                 | grep 数字与"为什么"对实测逐条核 |
| D6   | 被推翻的证据留在文档里     | 逐字段核对；作废换落点指针      |

**D1 计数 / 条数 / 阈值两边不等**
文档里写了数字的**当场数一遍**（`grep -c` / 脚本自报）。
例：文档写"22 条 = 5 + 17"，实测 24 条；同一批里另一处已改成不写死数。

**D2 改名后引用面没跟**（路径 / 分支名 / 镜像 tag）
改名后全仓 `grep -rn <旧名>`，确认 0 命中，或残留全是**历史叙述**（引用旧代码的注释、dated 记录）。
例：树改名后 8 个脚本仍写旧路径（其中 3 个带 `cd … || exit`，直接跑不起来）。

**D3 悬空引用**
移动 / 删除文件后搜引用；索引类文档要同步删行或改成**落点指针**。
例：笔记移入 archive 后，索引里那两行必须改成"已随线归档至 …"。

**D4 结论与实现方向相反**
判决只有两态时理由栏写"缺数据"，别在同一句里既写 ❌ 又写"不判负"（读者会当成第三种取值）。
例：同一句里"❌"与"**不判负**"并存。

**D5 动机句腐坏**：注释 / 文档里"因为 X 所以做 Y"的 X 是**实测量**，实测被推翻后动机句最晚腐坏（没人跑它）
`grep` 新增代码与文档里的**数字与"为什么"**，对最新实测表逐条核。
例：批量化的动机原写"88 次往返 = 7-15 ms"，实测证明往返次数不是主因（真因 = 共用连接排队）——9 处注释与文档要一起改，含测试 docstring。

**D6 被推翻的证据留在文档里**（假字段 / 旧格式日志片段）
文档里贴的日志片段逐个字段核对"这个数现在还有吗"；作废的证据换成**落点指针**，不重抄。
例：时序行旧格式含三个**恒 0 假字段**（初始化后从未累加），留在文档里等于把假证据当结论。

## E. 跨仓 / 跨机族

| 编号 | 症状                   | 怎么查（速查）             |
| ---- | ---------------------- | -------------------------- |
| E1   | 同源两份不一致         | 关键段或 md5 对比          |
| E2   | 坐标与机台事实靠默认值 | 逐项指回上一条同形轮的证据 |
| E3   | 越界动到归档面         | 确认不在归档/冻结集合      |

**E1 同源两份不一致**（代码 / 文档）
两端取同一文件的关键段或 md5 对比，别只比"看起来一样"。
例：双源仓库的 L2 代码必须逐项比功能差异清单。

**E2 坐标与机台事实靠默认值**
树名 / 镜像 / BDF / IP 逐项**指回上一条同形轮**的证据。
例：构建链的 `DOCKER_IMAGE`/`REPO_DIR` 显式传，至少核对启动日志的 tag。

**E3 越界动到归档面**
确认改动对象**不在归档/冻结集合**里——归档物不评审、不修复、不跑它的套件。
例：为归档分支补记版、跑归档 skill 的自证套件。

## F. 提交面族

| 编号 | 症状                        | 怎么办（速查）                  |
| ---- | --------------------------- | ------------------------------- |
| F1   | 路径限定没生效 / 吞别人暂存 | commit 只带列表内路径           |
| F2   | 重命名只提交一半            | 提交后查树                      |
| F3   | message 被写短              | 先落盘再 -F；重试复用同一文件   |
| F4   | 钩子改文件并中止提交        | 查 %s 关键词；add 后再提        |
| F5   | 改动历史时暂存被降级        | 事前存 patch，事后 add 回去 cmp |
| F6   | 变异自证写穿仓库文件        | 只在副本上变异；前后各核一次    |

**F1 路径限定没生效 / 吞了别人的暂存**
`git commit -F msg -- <paths>` **只带列表内路径**；**未跟踪文件必须先 `git add`**（否则报"未匹配任何 Git 已知文件"）。

**F2 重命名只提交一半**
`git mv` 后 `git commit -- <新名>` 只带新名一侧 ⇒ HEAD 里新旧并存。判据 = 提交后查**树**：`git ls-tree HEAD --name-only | grep <旧名>` 应为 0；补一笔带旧路径。

**F3 message 被写短**
message **先落盘**（`Write /tmp/<批>-msg.txt`）再 `git commit -F`；钩子中止后重试**逐字复用同一文件**——重打容易顺手写短，落库就成了短版（判据：`git log -1 --format=%B | wc -l`）。

**F4 钩子改文件并中止提交**
判据 = 提交后 `git log -1 --format=%s`，关键词没中就重试；该 `git add` 钩子改过的文件再提，**别 `--no-verify`**。

**F5 改动历史时暂存被降级**
`rebase --autostash` 会把**已暂存**的改动还原成未暂存（内容不丢）⇒ 事前 `git diff --cached > /tmp/staged.patch` + 记路径清单，事后 `git add` 回去并 `cmp` 验证逐字节还原。

**F6 变异自证写穿仓库文件**（"只读"变异副本其实写到了真文件）
变异**只在副本上做**（`cp` 到 `/tmp/<dir>` 再改），或先 `rm` 符号链接再写普通文件——`open(path,"w")` **会穿透符号链接**写进链接目标，覆盖层/链接农场最容易中招。**变异前后各核一次**：`git diff --stat`、`git status --short`、关键文件 md5 必须与事故前一致（"看起来还原了"不算，要数值相同）；失手 ⇒ `git show HEAD:<path>` 精确复原 + 复跑机械门与受影响的测试。
例：校对 agent 用符号链接覆盖层做变异，`open(...,"w")` 写穿覆盖层、覆盖了真实仓库的两个核心源文件（还误删了一段提交循环），自述已复原 ⇒ 独立复核靠 md5 与 `git diff --stat` 逐项对齐才确认无残留。
